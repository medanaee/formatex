# ADR 0007: The component library (user-defined tags, generated registry)

- **Status:** Accepted
- **Date:** October 2026

## Context

The engine's tags (`<alert>`, `<grid>`, ...) are **components**: one Typst file each in `components/`, exporting `<name>-tags` (the code), `<name>-schema` (the description autocomplete reads) and optionally `-rules` and `-scope`. A script in the engine (`tools/gen-registry.mjs`, Windows only) generates `components/_registry.typ`, which imports them all. Users need to define tags of their own, edit the existing ones, and later get tags from a server, with autocomplete working for all of them and without running a script.

## Decision

1. **The Rust side owns a component library** (`src-tauri/src/components.rs`): the built-in components embedded in the app plus the user's in `$APPDATA/components/<name>.typ`. A user file with a built-in's name **replaces** it (the built-in stays available: *Revert* deletes the user's version). `manifest.json` records disabled components and the **origin** of each (`user`, later `store`).
2. **The registry is generated by the app** (a port of `gen-registry.mjs`): same imports, sums and rule order, found by reading each file's `#let <name>-...` lines. A test checks that the generated registry for the built-ins equals the engine's own `_registry.typ`. A component that is invalid (no `-tags`, tags without a `-schema`, a tag already declared by another) is **left out of the registry and reported**, instead of breaking every document; a disabled component is left out too.
3. **The world serves `components/...` from the library** (`world.rs`): `_registry.typ` is the generated text, `components/<name>.typ` is the user's version or the built-in. A project cannot shadow any of it.
4. **The schema is computed, not bundled.** `engine_schema` compiles the engine's own `tools/schema.typ` (embedded; it imports the registry and exposes every schema as `<schemas>` metadata) and returns it as JSON. The result is cached until the library changes. The frontend starts with the bundled `engine/tags.json` and replaces it with this one, so **a new component's tags reach autocomplete as soon as its file is saved**.
5. **Every change is checked.** Saving, deleting or disabling a component recompiles `tools/schema.typ`; the result (`ok` and diagnostics with `components/<name>.typ:line`) is shown under the editor. This catches errors at module level (syntax, an unknown variable, a bad schema). A mistake inside a tag's function body shows when a document uses the tag, as an ordinary problem in the preview, which links to the component.
6. **The Components screen** lists every component (tags, built-in / custom / modified, an enable switch), opens one in a Typst editor (autosaved), creates a new one from a working template (inline or block), reverts a modified built-in and deletes a custom one.
7. **The library is global to the app**, like fonts, not per project: components are installed, not authored per document. (A document that uses a custom tag needs the component on the machine that compiles it; sharing a component is exporting its file.)

## Server store (planned)

A component is a single `.typ` file, so a store can serve files plus a small manifest (`name`, `version`, `description`, `files`, `author`, `license`). Installing writes the file with origin `store` through the same save path (`component_save(name, source, "store")`), which already validates and refreshes the schema. Updates compare versions; a user edit of a store component marks it modified like a built-in. Needed before it ships: a manifest format, signing or review, dependency declaration between components, and an ADR for the protocol.

## Alternatives Rejected

- **Per-project components:** more portable documents, but a project would carry engine code, the store would need per-project installs, and the registry would differ per compilation.
- **Editing the embedded built-ins in place:** impossible (read-only binary); copy-on-write with *Revert* gives the same result.
- **Parsing the schema from Typst source in TypeScript:** fragile; compiling the engine's own `schema.typ` gives the exact data the engine uses.

## Consequences

- A broken enabled component makes every compilation fail until it is fixed or disabled; the check and the *library does not load* banner exist to make that visible, and a problem in a component links straight to it.
- `tools/` is now engine-owned too (`tools/schema.typ`), next to `main.typ`, `src/`, `components/`.
- First load computes the schema (a compilation of the whole registry, seconds); later reads are cached.
- In a browser the library is localStorage only: no registry, no check, no new tags in autocomplete (there is no compiler).
