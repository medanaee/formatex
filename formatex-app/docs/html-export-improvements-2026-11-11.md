# HTML export improvements, 2026-11-11

## Scope and comparison boundaries

This update covers offline KaTeX packaging, browser-compatible formal serif fonts, native text/structural components, compact layout and the standalone cover component. It builds on [the live HTML pipeline work](performance-improvements-2026-11-10.md). Its file-size observations are separate from that report's large-document compilation timings; they do not establish an Android speedup or an end-to-end Tauri performance figure.

Charts, CeTZ, Lilaq and arbitrary Typst graphics intentionally retain their Typst SVG rendering. Text and structural components use native HTML with their existing attributes, rather than snapshots of their PDF layout.

The KaTeX bootstrap is emitted only when KaTeX math markers occur. A page without formulas does not carry the bundle. `tools/bundle-katex.mjs` in the engine generates `src/html/katex.typ` from `src/html/katex.assets.json`. The asynchronous renderer exposes `window.__fxMathReady`, and the live iframe waits for it before reporting paint on initial load and content updates. No CDN or other network resource is needed.

## Formal serif font fixes

Two separate problems affected formal Latin text. Real CMU Serif has a regular face with weight 500, which the old exact 400/700 filter could omit. Selection now independently chooses the nearest regular/bold face for each required style, while exact requested families still take precedence over aliases. Alias fallbacks emit the requested CSS family name.

Stock New Computer Modern's CFF outlines, both full and subset variants, were rejected by the tested browser even when repackaged as OTF/WOFF2. HTML now uses four quadratic-outline copies generated by `scripts/prepare-html-serif.py` from Typst assets 0.15.1 NewCM10 Regular, Bold, Italic and BoldItalic. The script uses fontTools, bounds curve approximation error at one font unit (about 0.001 em), and preserves metrics and GDEF/GPOS/GSUB shaping tables. The internal family is renamed `Formatex NewCM Web`; CSS retains the requested `New Computer Modern` family. Original PDF font selection is unchanged.

Generated files live in `src-tauri/web-fonts/`, alongside a README and the upstream NOTICE copied from Typst assets. The NOTICE contains the applicable GUST and GPL3 font/distribution exception notices. The subsetter's separate CFF flavor inconsistency is normalized and covered by a unit test. No unconditional CMU Serif embedding or duplicate New Computer Modern alias is needed.

Browser font-load checks now succeed for both formal New Computer Modern and real CMU Serif. These observations apply to the tested browser; Android hardware remains a separate validation target.

## Native components and mathematical references

Native HTML covers the standalone cover, docheader, paragraph, letter, tree, exercise/choices/answers, collected todos, chat, comparison, definitions, diff, progress, grid and steps. It preserves existing attribute behavior: chat defaults and three styles, comparison columns/colors/titles, progress variants and values, definition links, LCS split/unified diffs, responsive grid spans and sizing, image/figure geometry and selectable code with line numbers/highlight bands. Core counters, digits, lists, citations and bibliography remain native content. Graphics retain the rendering path described above.

Inline textual `<typ>` now emits native selectable headings and colored text. Source files and common vector operations retain SVG frames. HTML `<v>` creates an explicit height, page breaks use print-break CSS, and wavy/dash-dot horizontal rules use native CSS. Comparison markers remain correct with custom list markers; grid spans are clamped to the parent column count and preserve height/vertical alignment. Alignment and paragraph CSS specificity no longer overrides the tag's intended alignment.

Display math numbering explicitly steps its counter and resolves the equation's own metadata, so references no longer pick an earlier native equation. Standard and inline footnotes now produce native numbered references and one endnotes section containing their full content.

The cover is a body `<cover>` component. PDF gives it a standalone single-column page without header/footer/printed number and resets the following page to 1; HTML retains the effective page height and scrolls extra content internally. Old cover front matter/configuration/CLI switches have no effect; attributes and an optional Markdown body replace them.
